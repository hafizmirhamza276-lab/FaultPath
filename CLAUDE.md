# CLAUDE.md

Working notes for agents and humans touching this repo. Read `README.md` for the
full source-document audit and `METRICS.md` for metric definitions.

## What this is

Ground truth and measurement scaffolding for a guided diagnostic assistant built
over Komatsu Shop Manual **SEN06867-13** (PC200-10M0 Hydraulic Excavator,
S/N 700001 and up, revision 13, 2,226 pages).

This repo is **not** the assistant. It is the reference the assistant is scored
against, plus the audit of the source document it is built on.

```
pipeline/extract_golden.py   PDF -> structured diagnostic trees (deterministic)
pipeline/audit_manual.py     source-document data-quality audit
golden/                      the ground truth (committed)
reports/audit_findings.json  audit baseline (committed)
eval/                        evaluation harness (not yet implemented)
eval_out/, runs/             generated output (gitignored)
```

## Rule 1 — no LLM in extraction or Tier-1 evaluation

`extract_golden.py` uses deterministic parsing only. No model call belongs
anywhere in extraction or in Tier-1 scoring. That is the entire value
proposition: "our hallucination rate is 0.3%" is defensible line by line only
because nothing in the ground truth was generated by a model.

Tier-2 LLM-as-judge metrics are permitted, but must stay reported separately and
never be blended into a Tier-1 figure. See `METRICS.md`.

## Rule 2 — `golden/` is ground truth

`golden/failure_codes/*.json`, `golden/index.json` and `golden/qa_set.json` were
validated page-by-page against the source manual.

- **Never hand-edit them.** A hand-corrected value is indistinguishable from a
  parser bug on the next regeneration.
- **Never regenerate casually.** Regeneration is only valid together with the
  count check below. If the counts move, the parser changed behaviour — that is
  a regression to investigate, not a new baseline to accept.
- Changes to parsing logic, regexes, or `requirements.txt` pins can silently
  alter output. Table extraction is version-sensitive; the pins in
  `requirements.txt` are the versions that produced the committed data.

## Rule 3 — the manual never enters the repo

SEN06867-13 is Komatsu copyrighted material. It is gitignored (`*.pdf`, plus
`*-decrypted.pdf` for `qpdf --decrypt` normalised copies) and must be stored
outside the working tree.

Point the scripts at it with `KOMATSU_PDF`. Both scripts exit with a clear error
rather than running against a missing or wrong file.

```bash
pip install -r requirements.txt
export KOMATSU_PDF="/path/outside/this/repo/SEN06867-13.pdf"

python pipeline/extract_golden.py     # -> golden/
python pipeline/audit_manual.py       # -> reports/audit_findings.json
```

Path overrides, all resolved from the script's own location by default:

| Env var | Default | Meaning |
|---|---|---|
| `KOMATSU_PDF` | *(none — required)* | source manual |
| `GOLD_DIR` | `<repo>/golden` | ground-truth directory |
| `OUT_DIR` | `<repo>/reports` | audit report directory |

## Regression check

After any regeneration, these must hold exactly. Verified on 2026-09-10 with
pdfplumber 0.11.10 / pymupdf 1.28.2:

| Quantity | Expected |
|---|---|
| failure-code JSON files | 174 |
| total steps | 996 |
| total measurements (standalone + per-step) | 872 |
| YES/NO branch outcomes | 1,437 |
| codes with `is_pointer_only == true` | 9 |
| steps with `extraction_warning == "column_split_recovered"` | 27 |
| cross-reference edges | 94 |
| format split | 117 A / 57 B |

Audit baseline: **19 findings — 6 HIGH / 8 MEDIUM / 3 LOW / 2 INFO.**

Any deviation is a behaviour change. Report it loudly and investigate before
committing the regenerated data.

## Known state worth carrying forward

- `README.md` says "20 findings ... 3 informational"; the audit actually emits
  19 (2 INFO). The `H2` non-embedded-fonts finding does not fire, because font
  detection samples only every 37th page. Docs and data disagree here.
- `METRICS.md`'s case-type table sums to 1,241 but `qa_set.json` holds 1,330;
  its `numeric_exactness` (759) and `branch_following` (114) counts are stale
  against the actual 846 and 116.
- `CA451` step 6 carries the criterion `.2 to 4.6V`. The correct value is
  `0.2 to 4.6V` (confirmed by sibling code `CA452`). The `README.md` "Also found
  and repaired" section claims this was fixed; it was not, and audit check `E4`
  cannot detect it because it looks for a digit before the split point.
- 4 `qa_set.json` cases are duplicate questions with conflicting expected
  answers (`CA271` resistance at the same measuring point across two steps).
  They are unanswerable as written and cap `numeric_exactness` below 100%.
- Criteria strings mix `Ω` U+2126 (353) and U+03A9 (349). Any evaluator must
  NFC-normalise before verbatim comparison.
- `build_qa_set.py`, `evaluate.py` and `make_mock_runs.py` are documented in
  `README.md` but were never present. `eval/` is the intended home for them.
  `golden/qa_set.json` therefore cannot currently be regenerated from source.
